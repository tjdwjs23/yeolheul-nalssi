# 🌦️ 열흘날씨

**한 곳의 예보만 믿지 않는 10일 날씨.**

같은 날, 같은 동네 예보인데 기상청은 "맑음", 아큐웨더는 "비 90%"라고 하는 날이 있다.
그래서 예보 서비스 4곳을 한꺼번에 비교해서, 극단적인 값에 휘둘리지 않는 하나의 값으로
합쳐서 보여주는 페이지를 만들었다.

코드를 `update_weather.py`의 `REGIONS` 목록에 붙이면 다음 갱신부터 목록에 나타난다.

## 온도는 이렇게 계산한다

**4개 값에서 가장 높은 것과 가장 낮은 것을 하나씩 버리고, 남은 2개를 평균낸다.**

한 서비스가 유독 튀는 값을 내놓아도 결과가 흔들리지 않게 하기 위해서다.
최저온도·최고온도 모두 같은 방식이다.

### 오전 / 오후 기준온도

하루를 "최저 18° / 최고 29°"로만 보면 아침에 뭘 입을지 감이 안 온다.
그래서 출근길(오전 9시), 한낮(오후 1시), 퇴근·저녁(오후 7시)의 체감 기준온도를
따로 계산한다.

우선순위는 "실제 값이 있으면 그걸 쓰고, 없을 때만 근사"다.

1. **그날의 실제 시간별 예보값** — 시간별 예보가 제공되는 날(보통 오늘~모레)은
   그 날짜의 실제 9시·13시·19시 온도(4사 최고·최저 제외 평균)를 그대로 쓴다.
2. **기준일 비율 근사** — 시간별이 없는 먼 날짜는, 시간별이 있는 기준일
   (그 시각이 지났으면 다음날)에서 "일교차 대비 위치 비율"을 뽑아 전달한다:

   ```
   비율 = (기준일 그 시각 온도 − 기준일 최저) ÷ 기준일 일교차
   먼 날짜 기준온도 = 그날 최저 + 그날 일교차 × 비율
   ```

   절대 차이(+4° 식)가 아니라 비율을 쓰는 이유: 일교차는 날마다 다르다.
   일교차 15°인 기준일에서 뽑은 +6°를 일교차 4°인 날에 더하면 오전 기온이
   최고기온을 넘어버린다. 비율은 그날의 일교차에 맞게 자동으로 줄어든다.
   비율은 시간대별 안전 범위로 제한한다(오전 0.15~0.50, 오후 0.60~1.00,
   저녁 0.10~0.80). 기준일 일교차가 2° 미만이면 비율이 불안정해 3번으로 넘어간다.
3. **예비 공식** — 시간별 예보를 아예 못 구한 경우:
   `오전 = 최저 + 일교차 × ((9시−일출)/(15시−일출), 0.20~0.40 제한)`,
   `오후 = 최저 + 일교차 × 0.85`, `저녁 = 최저 + 일교차 × 0.40`.
   일출시각은 네이버 데이터의 위도·경도로 천문 공식(NOAA 근사식)으로 직접 계산한다.

**강수확률도 같은 우선순위다** — 시간별이 있는 날은 그 시각(9·13·19시)의 실제 확률
(4사 통합)을 쓰고, 없는 날은 일자별 오전/오후 확률로 대체한다. 저녁의 대체값은
오후 확률인데, 기상청 기준 '오후'가 정오~자정을 포함하므로 근사로 무리가 없다.

### 옷차림 — 하루 한 벌

옷은 아침에 한 번 입고 나가면 끝이다. 그래서 시간대별로 따로 추천하지 않고,
세 시간대(9시·13시·19시) 기준온도를 모두 고려한 **하루 한 벌**을 추천한다.
레이어링 원리를 따른다:

- **상의** = 가장 따뜻한 시간대의 기온 구간 기준 — 한낮에 덥지 않게
- **외투** = 가장 추운 시간대의 기온 구간 기준 — 아침·저녁에 걸치게

일교차가 큰 환절기에는 "반팔 + 재킷"처럼 나오는데, 그게 정확히 의도다.
기온 구간별 옷차림표(민소매 ~ 패딩, 8구간)는 흔히 쓰이는 기준을 따랐다.

### 열흘 요약 — 평년(1991~2020) 대비

페이지 상단에 이번 열흘이 평년보다 얼마나 따뜻한지/추운지를 한 줄로 요약한다.
기상청은 2021년 4월부터 1991~2020년 평년값을 사용하는데, 갱신할 때마다
[기상자료개방포털의 기후평년값](https://data.kma.go.kr/climate/average30Years/selectAverage30YearsList.do?pgmNo=113)에서
서울(108) 지점의 **공식 일별 평년값**(일최저·일최고)을 예보 기간만큼 조회해,
열흘치 예보 최저/최고와의 차이를 각각 평균낸다. 조회에 실패한 회차에는 요약 카드만
조용히 생략된다.

> 열흘 요약 · 평년(1991~2020, 서울 기준) 대비
> 최저기온 2.3° 높음 · 최고기온 3.6° 높음

평년 기준은 전 지역 공통으로 서울 하나만 쓴다 — 요약의 목적이 "평년 대비 체감"이라
지역별 관측소를 나누는 정밀도까지는 필요 없다고 봤다. ±0.3° 이내면 "평년 수준"으로
표시한다. 함께 열흘 중 비 올 만한 날(통합 확률 60% 이상인 날) 수도 보여준다.

### 계절감

날짜가 아니라 그날의 기온으로 "어느 계절처럼 느껴지는지"를 판정해서 함께 표시한다.
"지금이 무슨 계절인가"의 판정이 아니다 — 기상청의 공식 계절 구분은 9일 이동평균과
지속성 조건을 쓰는 반면, 이건 하루치 기온의 스냅샷이라 비 오는 날 하루만 "초가을
날씨"가 됐다가 다음 날 "늦여름 날씨"로 돌아올 수 있고, 그게 의도된 동작이다.
그래서 표기도 "늦여름"이 아니라 **"늦여름 날씨"** 다. 옷차림 추천은 이 라벨이 아니라
오전/오후 기준온도로 직접 계산하므로, 계절감 분류가 애매한 날에도 추천은 영향받지
않는다. 일평균기온은 (최저+최고)/2로 근사한다.

**평균기온이 구간을 정하고, 날짜가 이름(상승기/하강기)을 가른다.** 구간은
반개구간 [a, b)이라 정확히 10.0°, 15.0° 같은 경계값이 두 곳에 걸리지 않는다.

| 평균기온 | 상승기 | 하강기 |
|---|---|---|
| 25° 이상 + 최고 30° 이상 | 한여름 | 한여름 |
| 20~25° | 초여름 | 늦여름 |
| 15~20° | 늦봄 | 초가을 |
| 10~15° | 봄 | 가을 |
| 5~10° | 초봄 | 늦가을 |
| 5° 미만 | 늦겨울 | 초겨울 |
| 0° 이하 + 최저 -5° 이하 | 한겨울 | 한겨울 |

상승기/하강기는 월이 아니라 날짜로 정한다 — 서울 기준 가장 추운 시기(1/20)부터
가장 더운 시기(8/1)까지가 상승기, 8/2~1/19가 하강기다. 같은 평균 12°라도 4월이면
"봄", 11월이면 "가을"이 된다. 날짜는 계절을 결정하는 값이 아니라 기온이 올라가는
중인지 내려가는 중인지만 알려주는 방향 장치다.

최저·최고기온은 이름 결정에 쓰지 않고, 극단 구간(한여름·한겨울) 판정에만 보조로
쓴다 — 평균 26°라도 최고가 30°에 못 미치면 한여름이 아니라 초/늦여름이다.

## 강수확률은 이렇게 계산한다

**단순 평균은 쓰지 않는다.** `0 / 0 / 0 / 90` 같은 날 단순평균을 내면 22.5%가 되는데,
실제로는 4곳 중 3곳이 "비 안 온다"고 보는 날이다. 한 서비스의 극단값이 전체 판단을
끌고 가면 안 된다.

### 통합값 = 중앙값

```
확률 = 4사 강수확률의 중앙값 (가운데 두 값의 평균)
```

처음에는 "중앙값 80% + 서비스별 신뢰도 가중평균 20%"와 "3곳 이상 합의 시 상·하한"
규칙을 함께 썼지만, 리뷰를 거쳐 둘 다 걷어냈다.

- **가중평균 제거** — 서비스별 가중치(KMA 0.40 …)는 검증된 근거가 없는 추정이었다.
  근거 없는 정밀함은 복잡도만 더한다. 실제 강수 결과를 기록해 Brier Score가 쌓이면
  그때 재도입을 검토한다.
- **합의 규칙 제거** — "3곳이 20% 이하면 최대 20%" 같은 규칙은 중앙값이 수학적으로
  이미 보장한다(3곳이 ≤20이면 중앙값도 반드시 ≤20). 중복 규칙은 설명만 복잡하게
  만든다.

유일하게 남긴 특수 규칙: **2곳 ≥60% + 2곳 ≤20%로 완전히 갈린 날**은 확률은 그대로
두고 일치도만 "예보 크게 엇갈림"으로 강등한다. 불확실성과 확률은 다른 축이고,
"이 확률은 믿을 만한 확률이 아니다"라는 정보는 일치도가 전달해야 하기 때문이다.

### 문구

"안 옴", "비 옴" 같은 확정적 표현은 쓰지 않는다. 예보는 확률이니까. 그리고 확률
문구는 **사건 확률만** 말한다 — 네 업체가 전부 50%로 일치한 날과 0/100으로 갈린
날은 문구가 아니라 일치도로 구분된다.

| 최종 확률 | 문구 | 짧은 표시 |
|---|---|---|
| 0~19% | 비 가능성 매우 낮음 | 거의 안 옴 |
| 20~39% | 비 가능성 낮음 | 가능성 낮음 |
| 40~59% | 비가 올 수도 있음 | 가능성 반반 |
| 60~79% | 비 올 가능성 높음 | 가능성 높음 |
| 80~100% | 비 올 가능성 매우 높음 | 비 유력 |

### 예보 일치도 — 확률과는 별개의 값

"강수확률 40%"라도 두 가지 상황이 있다.
`35/40/40/45`는 4곳이 모두 40% 근처로 보는 것이고, `0/20/80/100`은 예보가 완전히
갈린 것이다. 확률 숫자만으로는 이 차이가 안 보이기 때문에, **최고 확률 - 최저 확률
(Spread)** 로 일치도를 따로 계산해 함께 보여준다.

| Spread | 일치도 |
|---|---|
| 20 이하 | 예보 일치도 높음 |
| 21~40 | 예보 일치도 보통 |
| 41~60 | 예보 일치도 낮음 |
| 61 이상 | 예보 크게 엇갈림 |

다만 Spread를 그대로 쓰면 이 지표만 극단값 하나에 100% 휘둘리는 자기모순이 생긴다.
`40/40/40/100`은 Spread가 60이라 "일치도 낮음"이 되지만, 실제로는 3곳이 완벽하게
일치하고 하나만 튄 **3:1 소수의견** 상황이다. 진짜로 갈린 `10/35/65/90`과는 다르게
봐야 한다.

그래서 3곳이 20%p 이내로 뭉쳐 있고 나머지 하나만 40%p 이상 튀는 경우에는
일치도를 **합의된 3곳의 Spread로** 계산한다. `0/0/0/90`은 "일치도 높음"이 된다 —
극단값 하나가 결론을 정하게 두지 않는다는 원칙을 일치도에도 똑같이 적용한 것이다.

그래서 화면에는 "57% · 가능성 있음"과 "예보 크게 엇갈림"이 같이 표시될 수 있다.
그런 날은 우산을 챙기는 게 낫다.

## 참고한 생각들

- 강수확률은 하늘 상태(맑음/흐림)와 별개의 요소다. 기상청도 강수확률을 "현재와 유사한
  대기 상태에서 지정된 장소에 강수가 내릴 가능성"으로 정의한다. 그래서 확률이 50%라고
  "흐림"이라고 표현하지 않는다.
- 옷차림표는 흔히 쓰이는 기온별 옷차림 기준(28° 이상 민소매 ~ 4° 이하 패딩)을 따랐다.
- 온도의 "최고·최저 제외 평균"과 강수의 "중앙값 중심 통합"은 결국 같은 철학이다:
  **한 서비스의 극단값이 결론을 정하게 두지 않는다.**

## 파일 구성

- `update_weather.py` — 네이버 비교 페이지를 읽어 위 계산을 수행하고 `data.json` 생성
- `index.html` — `data.json`을 읽어 보여주는 페이지 (지난 날짜는 자동으로 숨김)
- `.github/workflows/update.yml` — 하루 3번 자동 갱신
